<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser->route-handlers | Username and password cross from an untrusted browser into server login code. |
| route-handlers->postgres | Auth routes mutate and read credential records from the server database. |
| dependency-install->repository | New framework and runtime packages enter the codebase during the bootstrap task. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | src/app/api/auth/login/route.ts | mitigate | Validate username and password against scrypt hashes, reject inactive users, and issue signed session cookies only after successful verification. |
| T-01-02 | Tampering | src/lib/auth/server-session.ts | mitigate | Sign the server session envelope with SESSION_SECRET and reject malformed or password-version-mismatched cookies. |
| T-01-03 | Repudiation | prisma/seed.ts and login audit model | mitigate | Persist a login-audit row with user id and timestamp for every successful online login. |
| T-01-SC | Tampering | npm package installs | mitigate | Keep the blocking package-legitimacy checkpoint before first install and only continue after human approval of official packages. |
</threat_model>
