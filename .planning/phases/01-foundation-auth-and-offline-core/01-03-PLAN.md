<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cached-shell->browser | Shell assets and UI state are replayed from a service worker on an untrusted device. |
| service-worker->auth-routes | The service worker sits near auth-related network traffic and must not cache sensitive mutation responses. |
| keyboard-contract->future-pos-actions | Future POS screens will bind privileged keyboard actions to the registry introduced here. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-07 | Tampering | public/sw.js | mitigate | Explicitly exclude login, logout, and session mutation responses from service-worker caching and keep shell cache names versioned for safe rotation. |
| T-01-08 | Information Disclosure | src/app/offline/page.tsx and cached shell assets | mitigate | Keep offline shell pages free of secrets, mask sensitive user data in cached chrome, and rely on local session policy from Plan 02 before rendering protected content. |
| T-01-09 | Elevation of Privilege | src/lib/shortcuts/pos-contract.ts | mitigate | Publish reserved keyboard action identifiers only; do not bind privileged checkout behavior until the POS phase adds route- and role-aware handlers. |
| T-01-SC | Tampering | npm package installs | mitigate | Reuse only the package set already approved in Plan 01 and avoid introducing additional UI/PWA packages without another legitimacy checkpoint. |
</threat_model>
