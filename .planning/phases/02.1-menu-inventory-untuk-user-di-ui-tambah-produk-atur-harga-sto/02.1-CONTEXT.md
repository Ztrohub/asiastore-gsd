**Gathered:** 2026-05-18
**Status:** Ready for planning

<domain>
## Phase Boundary

Membangun menu Inventory pada UI untuk operasi tambah produk, atur harga, stock in, dan stock adjustment yang cepat dipakai operator, konsisten dengan arsitektur offline-first, serta terhubung ke engine event mutasi/sinkronisasi yang sudah dikunci di Phase 2.

</domain>

<decisions>
## Implementation Decisions

### Struktur form inventory
- **D-01:** Inventory UI memakai satu halaman dengan 3 tab utama: `Produk`, `Stock In`, `Stock Adjustment`.
- **D-02:** Aksi tambah produk dilakukan via modal popup (bukan inline form).
- **D-03:** Setelah produk tersimpan, tetap di tab `Produk` dan form di-reset untuk input beruntun.
- **D-04:** Daftar produk ditampilkan dalam tabel ringkas dengan search.

### Aturan harga dan validasi
- **D-05:** Input harga diketik sebagai angka mentah, lalu auto-format ke IDR saat field blur.
- **D-06:** Validasi harga: minimal `Rp100`, maksimal `Rp999.999.999`.
- **D-07:** Harga produk tetap bisa diubah walau produk sudah dipakai transaksi/mutasi; perubahan hanya berlaku untuk transaksi baru.
- **D-08:** Harga desimal tidak diperbolehkan; harga disimpan sebagai integer tanpa pecahan.

### UX stock in vs stock adjustment
- **D-09:** `Stock In` dan `Stock Adjustment` dipisah sebagai dua tab aksi terpisah.
- **D-10:** Pada `Stock Adjustment`, input utama adalah stok akhir absolut; sistem menghitung delta otomatis.
- **D-11:** Perubahan stok ke nilai minus tetap memakai soft warning dan transaksi tetap bisa lanjut.
- **D-12:** Setelah submit mutasi, tampil toast sukses dan form reset, tetap di tab yang sama.

### the agent's Discretion
- Detail microcopy pesan, urutan fokus keyboard antar field, dan detail visual densitas tabel ditentukan saat planning/execution selama tidak melanggar D-01 s.d. D-12.

</decisions>

- Local-first persistence via Dexie lalu background sync saat online.
- UI domain memakai komponen shadcn/base-ui wrapper dengan Tailwind utility classes.
- Bahasa UI Indonesia + format IDR/Jakarta sudah menjadi pola fase awal.

### Integration Points
- Route inventory UI baru perlu terhubung ke app shell authenticated (`src/app/app/*`).
- Submit `Stock In`/`Stock Adjustment` harus menulis event ke store lokal lalu enqueue ke `syncQueue`.
- Edit harga produk perlu konsisten dengan model server Prisma dan snapshot histori transaksi di fase POS nanti.

## Specific Ideas

- Operator butuh alur cepat: modal tambah produk, submit sukses, langsung lanjut input berikutnya tanpa pindah konteks.
- Pricing harus aman dari typo besar: angka mentah cepat diketik, validasi min/max, lalu auto-format IDR.
- Stock adjustment harus minim ambiguitas: user isi stok akhir, sistem hitung delta.
