## Findings

### HIGH-01: Last-write-wins conflict guard missing on product upsert
- File: `src/lib/db/product-catalog.ts:20`
- Impact: Older offline payload from another device can overwrite newer server state (`harga_jual`, `stok_saat_ini`, `nama_produk`) because incoming `updatedAt` is accepted but ignored.
- Why this matters: Project constraints require tolerating concurrent edits from 1-3 active devices. Current implementation always updates row regardless of event recency.
- Evidence:
  - `updatedAt` exists in input type but is never used in `upsertProduct`.
  - `update` path always writes values unconditionally.
- Recommendation:
  - Persist and compare a monotonic version (`updatedAt` client timestamp, logical clock, or server revision).
  - Reject or merge stale writes (e.g., only update when incoming timestamp >= stored timestamp).

### MEDIUM-01: Product deactivation/tombstone cannot propagate to local cache
- File: `src/lib/db/product-catalog.ts:13`
- Impact: Deactivated products can remain in client IndexedDB indefinitely because API only returns active products and client sync only upserts returned rows.
- Evidence:
  - `listProducts()` filters `where: { is_active: true }`.
  - `syncFromServer()` in `src/features/inventory/hooks/use-product-catalog.ts` does not remove or mark missing local rows inactive.
- Recommendation:
  - Return inactive rows as tombstones (`is_active=false`) or include a separate deleted/deactivated feed.
  - On client sync, apply tombstones and/or reconcile missing IDs explicitly.

### MEDIUM-02: Runtime type mismatch risk for `updatedAt` in offline product records
- File: `src/features/inventory/hooks/use-product-catalog.ts:68`
- Impact: Server JSON typically serializes Prisma `updatedAt` as ISO string, but local type expects `number`. Current code stores `updatedAt` as-is when truthy, risking invalid local shape and unstable ordering/filter logic downstream.
- Evidence:
  - `ProductRecord.updatedAt` is numeric in `src/lib/offline/db.ts`.
  - `syncFromServer()` writes `updatedAt: product.updatedAt ?? Date.now()` without normalizing string/date to epoch number.
- Recommendation:
  - Normalize on ingest, e.g. `updatedAt: typeof p.updatedAt === "number" ? p.updatedAt : Date.parse(String(p.updatedAt)) || Date.now()`.
  - Add a test for server payload with ISO timestamp.
