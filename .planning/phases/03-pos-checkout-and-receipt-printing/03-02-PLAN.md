<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cart->checkout-ledger | Cart state and payment inputs are converted into authoritative transaction records. |
| local-ledger->inventory-mutations | A completed sale emits stock-out side effects that must stay consistent with the saved transaction. |
| pos-sync-client->pos-sync-api | Queued POS transactions cross from offline cache into authenticated server persistence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | src/features/pos/hooks/use-pos-checkout.ts | mitigate | Recompute totals and change from canonical cart data at submit time rather than trusting dialog field echoes. |
| T-03-05 | Repudiation | src/lib/db/pos-transactions.ts | mitigate | Persist transaction id, user, payment type, note, and line snapshot in one local-first commit before side effects fire. |
| T-03-06 | Spoofing | src/app/api/sync/pos-transactions/route.ts | mitigate | Require authenticated session and reject malformed or duplicate transaction payloads. |
| T-03-SC | Tampering | sync-queue reuse | mitigate | Keep POS transaction sync rows under a distinct entity type and transport path from inventory mutations. |
</threat_model>
