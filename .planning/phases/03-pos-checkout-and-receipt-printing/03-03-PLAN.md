<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| saved-transaction->receipt-payload | Internal transaction data is transformed into a customer-visible receipt string. |
| app->local-print-bridge | Browser app sends receipt payloads to a device-local bridge outside the web app trust boundary. |
| receipt-prompt->new-transaction-reset | Print/skip decision must not leave the cashier in a partially completed transaction state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07 | Information Disclosure | src/features/pos/lib/receipt-format.ts | mitigate | Explicitly whitelist receipt fields and exclude the internal transaction note from printed output. |
| T-03-08 | Denial | src/features/pos/lib/print-bridge.ts | mitigate | Keep the bridge call one-shot and non-blocking so print failures cannot trap the cashier in a modal loop. |
| T-03-09 | Repudiation | src/features/pos/hooks/use-receipt-printing.ts | mitigate | Tie the prompt and bridge action to the already-saved transaction snapshot so print behavior cannot alter transaction completion state. |
| T-03-SC | Tampering | external local bridge | mitigate | Treat the bridge as an external dependency with strict payload formatting and explicit error handling rather than coupling completion to bridge success. |
</threat_model>
